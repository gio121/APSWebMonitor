# English and Spanish interface

APS Monitor supports English (`en-GB`) and Spanish (`es-ES`). The compact ES/EN button sits beside sign-out at the bottom of the sidebar, and in the top-right corner of the login screen. It selects the other language, saves a browser preference for one year, and reloads the same page including its query and fragment. Each browser has its own selection; English remains the default. Existing unsaved-form navigation protection also applies to a language change.

The neutral English catalogue is `Resources/MonitorResources.resx`; Spanish translations are in `Resources/MonitorResources.es.resx`. Add each interface key to both. Razor markup uses `Ui["Label"]` or `Ui["Message {0}", argument]`. Component code and services use `MonitorResources.Text` and `MonitorResources.Format`, which resolve the current async context's language. JavaScript charts receive translated labels from their calling component. `MonitorMudLocalizer` supplies translations for common component-library labels.

`MonitorLocalization.Configure` accepts only the explicit culture cookie and supports the two listed cultures. Changing a language does not mutate global thread defaults or another browser's culture. The `/culture` endpoint validates the language and local return URL, sets an HTTP-only preference cookie, and redirects back. The HTML language attribute and number formatting follow the selected culture. Dates retain day/month/year ordering; time-zone selection is unchanged.

Stored role names, permission keys, routes, synoptic types, JSON fields, InfluxDB fields, and device protocols remain unchanged. Built-in names are translated only for display. User-authored names, existing project content, and device-originated messages retain their original content. The English-first CMFX import preference is unchanged and still preserves the separate Spanish and English descriptions. Switching the interface language does not rewrite imported data. Human-facing export headings follow the interface language, while delimiters and invariant numeric encoding are preserved.

Run `dotnet run --project tests/LocalizationChecks` to verify both catalogues, formatted arguments, isolated culture selection, cookie persistence, safe redirects, button rendering and navigation, CMFX preference, and compatibility. Existing control-event and project-loading checks also render the monitor with imported fixture content.
